Skills 可以指示 agent 运行 shell 命令，并在 `scripts/` directory 中打包可复用 script。本指南介绍一次性命令、带有自有依赖的自包含 script，以及如何为 agent 使用场景设计 script 接口。

## 一次性命令

当现有包已经能满足你的需求时，可以在 `SKILL.md` instructions 中直接 reference 它，而不需要 `scripts/` directory。许多生态系统都提供了能在运行时自动解析依赖的 tool。

<Tabs sync={false}>
 <Tab title="uvx">
 [uvx](https://docs.astral.sh/uv/guides/tools/) 会在隔离环境中运行 Python 包，并进行激进缓存。它随 [uv](https://docs.astral.sh/uv/) 一起提供。

 ```bash
 uvx ruff@0.8.0 check .
 uvx black@24.10.0 .
 ```

 - 不随 Python 捆绑，需要单独安装。
 - 速度快。缓存积极，因此重复运行几乎是即时的。
 </Tab>
 <Tab title="pipx">
 [pipx](https://pipx.pypa.io/) 会在隔离环境中运行 Python 包。可通过操作系统包管理器安装（`apt install pipx`、`brew install pipx`）。

 ```bash
 pipx run 'black==24.10.0' .
 pipx run 'ruff==0.8.0' check .
 ```

 - 不随 Python 捆绑，需要单独安装。
 - `uvx` 的成熟替代方案。虽然 `uvx` 已成为标准推荐，但 `pipx` 仍然是可靠选择，并且在更多操作系统包管理器中可用。
 </Tab>
 <Tab title="npx">
 [npx](https://docs.npmjs.com/cli/commands/npx) 会运行 npm 包，并按需下载。它随 npm 一起提供，而 npm 随 Node.js 一起提供。

 ```bash
 npx eslint@9 --fix .
 npx create-vite@6 my-app
 ```

 - 随 Node.js 捆绑，无需额外安装。
 - 下载包、运行包，并缓存以备后续使用。
 - 使用 `npx package@version` 固定版本以保证可复现性。
 </Tab>
 <Tab title="bunx">
 [bunx](https://bun.sh/docs/cli/bunx) 是 Bun 中对应 `npx` 的 tool。它随 [Bun](https://bun.sh/) 一起提供。

 ```bash
 bunx eslint@9 --fix .
 bunx create-vite@6 my-app
 ```

 - 在基于 Bun 的环境中可作为 `npx` 的直接替代。
 - 仅当 user 环境中有 Bun 而不是 Node.js 时才适用。
 </Tab>
 <Tab title="deno run">
 [deno run](https://docs.deno.com/runtime/reference/cli/run/) 可以直接从 URL 或 specifier 运行 script。它随 [Deno](https://deno.com/) 一起提供。

 ```bash
 deno run npm:create-vite@6 my-app
 deno run --allow-read npm:eslint@9 -- --fix .
 ```

 - 文件系统/网络访问需要 permission 标志（`--allow-read` 等）。
 - 使用 `--` 分隔 Deno 标志和 tool 自身的标志。
 </Tab>
 <Tab title="go run">
 [go run](https://pkg.go.dev/cmd/go#hdr-Compile_and_run_Go_program) 会直接编译并运行 Go 包。它内置于 `go` 命令。

 ```bash
 go run golang.org/x/tools/cmd/goimports@v0.28.0 .
 go run github.com/golangci/golangci-lint/cmd/golangci-lint@v1.62.0 run
 ```

 - 内置于 Go，无需额外 tool。
 - 固定版本或使用 `@latest`，让命令更明确。
 </Tab>
</Tabs>

**在 skills 中使用一次性命令的建议：**

- **固定版本**（例如 `npx eslint@9.0.0`），让命令随时间保持一致行为。
- **在 `SKILL.md` 中 说明 prerequisites**（例如“需要 Node.js 18+”），而不是假设 agent 环境已经具备。对于运行时级别要求，请使用 [`compatibility` frontmatter field](/specification#compatibility-field)。
- **把复杂命令移入 script。** 当你只是用少量标志调用 tool 时，一次性命令很合适。当命令复杂到难以一次写对时，放在 `scripts/` 中的已测试 script 更可靠。

## 从 `SKILL.md` reference script

使用**相对于 skill directory 根 directory 的路径**来 reference 打包 file。 agent 会自动解析这些路径，不需要绝对路径。

在 `SKILL.md` 中列出可用 script，让 agent 知道它们存在：

```markdown SKILL.md
## 可用 script

- **`scripts/validate.sh`** — validation 配置 file
- **`scripts/process.py`** — 处理输入数据
```

然后指示 agent 运行它们：

````markdown SKILL.md
## workflow

1. 运行 validation script：
 ```bash
 bash scripts/validate.sh "$INPUT_FILE"
 ```

2. 处理结果：
 ```bash
 python3 scripts/process.py --input results.json
 ```
````

<Note>
同样的相对路径约定也适用于 `references/*.md` 这类支持 file。代码块中的 script execution 路径相对于 **skill directory 根 directory**，因为 agent 会从那里运行命令。
</Note>

## 自包含 script

当你需要可复用逻辑时，可以在 `scripts/` 中打包一个内联声明依赖的 script。 agent 只需一条命令即可运行该 script，不需要单独的清单 file 或安装步骤。

多种语言支持内联依赖声明：

<Tabs sync={false}>
 <Tab title="Python">
 [PEP 723](https://peps.python.org/pep-0723/) 定义了内联 scriptmetadata 的标准格式。请在 `# ///` 标记内的 TOML 块中声明依赖：

 ```python scripts/extract.py
 # /// script
 # dependencies = [
 # "beautifulsoup4",
 # ]
 # ///

 from bs4 import BeautifulSoup

 html = '<html><body><h1>Welcome</h1><p class="info">This is a test.</p></body></html>'
 print(BeautifulSoup(html, "html.parser").select_one("p.info").get_text())
 ```

 使用 [uv](https://docs.astral.sh/uv/) 运行（推荐）：

 ```bash
 uv run scripts/extract.py
 ```

 `uv run` 会创建隔离环境、安装声明的依赖并运行 script。[pipx](https://pipx.pypa.io/)（`pipx run scripts/extract.py`）也支持 PEP 723。

 - 使用 [PEP 508](https://peps.python.org/pep-0508/) specifier 固定版本：`"beautifulsoup4>=4.12,<5"`。
 - 使用 `requires-python` 约束 Python 版本。
 - 使用 `uv lock --script` 创建 lockfile，以实现完整可复现性。
 </Tab>
 <Tab title="Deno">
 Deno 的 `npm:` 和 `jsr:` import specifier 让每个 script 默认自包含：

 ```typescript scripts/extract.ts
 #!/usr/bin/env -S deno run

 import * as cheerio from "npm:cheerio@1.0.0";

 const html = `<html><body><h1>Welcome</h1><p class="info">This is a test.</p></body></html>`;
 const $ = cheerio.load(html);
 console.log($("p.info").text());
 ```

 ```bash
 deno run scripts/extract.ts
 ```

 - 对 npm 包使用 `npm:`，对 Deno 原生包使用 `jsr:`。
 - 版本 specifier 遵循 semver：`@1.0.0`（精确）、`@^1.0.0`（兼容）。
 - 依赖会全局缓存。使用 `--reload` 强制重新获取。
 - 带有原生 addon（node-gyp）的包可能无法工作，预构建二进制包效果最好。
 </Tab>
 <Tab title="Bun">
 当找不到 `node_modules` directory 时，Bun 会在运行时自动安装缺失包。请直接在 import 路径中固定版本：

 ```typescript scripts/extract.ts
 #!/usr/bin/env bun

 import * as cheerio from "cheerio@1.0.0";

 const html = `<html><body><h1>Welcome</h1><p class="info">This is a test.</p></body></html>`;
 const $ = cheerio.load(html);
 console.log($("p.info").text());
 ```

 ```bash
 bun run scripts/extract.ts
 ```

 - 不需要 `package.json` 或 `node_modules`。 TypeScript 可原生运行。
 - 包会全局缓存。首次运行会下载，后续运行几乎即时。
 - 如果 directory 树上层任何位置存在 `node_modules` directory，自动安装会被禁用，Bun 会回退到标准 Node.js 解析。
 </Tab>
 <Tab title="Ruby">
 Bundler 自 Ruby 2.6 起随 Ruby 提供。使用 `bundler/inline` 在 script 中直接声明 gems：

 ```ruby scripts/extract.rb
 require 'bundler/inline'

 gemfile do
 source 'https://rubygems.org'
 gem 'nokogiri'
 end

 html = '<html><body><h1>Welcome</h1><p class="info">This is a test.</p></body></html>'
 doc = Nokogiri::HTML(html)
 puts doc.at_css('p.info').text
 ```

 ```bash
 ruby scripts/extract.rb
 ```

 - 显式固定版本（`gem 'nokogiri', '~> 1.16'`），因为没有 lockfile。
 - 工作 directory 中已有的 `Gemfile` 或 `BUNDLE_GEMFILE` 环境变量可能产生干扰。
 </Tab>
</Tabs>

## 为 agent 使用设计 script

当 agent 运行你的 script 时，它会读取 stdout 和 stderr 来决定下一步怎么做。一些设计选择可以显著降低 agent 使用 script 的难度。

### 避免交互式提示

这是 agent execution 环境的硬性要求。 agent 在非交互式 shell 中运行，无法响应 TTY 提示、密码对话框或确认菜单。阻塞在交互式输入上的 script 会无限挂起。

通过命令行标志、环境变量或 stdin 接收所有输入：

```
# Bad: hangs waiting for input
$ python scripts/deploy.py
Target environment: _

# Good: clear error with guidance
$ python scripts/deploy.py
Error: --env is required. Options: development, staging, production.
Usage: python scripts/deploy.py --env staging --tag v1.2.3
```

### 用 `--help` 记录用法

`--help` 输出是 agent 了解 script 接口的主要方式。请包含简短 description、可用标志和用法示例：

```
用法：scripts/process.py [OPTIONS] INPUT_FILE

处理输入数据并生成摘要报告。

选项：
 --format FORMAT 输出格式：json、 csv、 table（默认：json）
 --output FILE 写入 FILE，而不是 stdout
 --verbose 将进度打印到 stderr

示例：
 scripts/process.py data.csv
 scripts/process.py --format csv --output report.csv data.csv
```

保持简洁，因为这些输出会与 agent 正在处理的其他内容一起进入 context 窗口。

### 编写有帮助的错误消息

当 agent 遇到错误时，错误消息会直接影响它下一次尝试。不透明的 “Error: invalid input” 会浪费一轮。请 instructions 出了什么问题、期望什么，以及可以尝试什么：

```
错误：--format 必须是以下之一：json、 csv、 table。
 收到："xml"
```

### 使用 structured 输出

优先使用 structured 格式（JSON、 CSV、 TSV），而不是自由文本。 structured 格式既能被 agent 消费，也能被标准 tool（`jq`、`cut`、`awk`）消费，从而让 script 可组合进管道。

```
# Whitespace-aligned — hard to parse programmatically
NAME STATUS CREATED
my-service running 2025-01-15

# Delimited — unambiguous field boundaries
{"name": "my-service", "status": "running", "created": "2025-01-15"}
```

**分离数据和 diagnostic 信息：** 将 structured 数据发送到 stdout，将进度消息、警告和其他 diagnostic 信息发送到 stderr。这样 agent 可以捕获干净、可解析的输出，同时在需要时仍能访问 diagnostic 信息。

### 进一步考虑

- **幂等性。** agent 可能会重试命令。“如果不存在则创建”比“创建并在重复时失败”更安全。
- **输入约束。** 对模糊输入给出清晰错误，而不是猜测。尽可能使用枚举和封闭集合。
- **Dry-run 支持。** 对于破坏性或有状态操作，`--dry-run` 标志可以让 agent 预览将发生什么。
- **有意义的退出码。** 为不同失败类型（未找到、参数无效、认证失败）使用不同退出码，并在 `--help` 输出中记录它们，让 agent 知道每个退出码的含义。
- **安全默认值。** 根据风险级别，考虑破坏性操作是否应要求显式确认标志（`--confirm`、`--force`）或其他保护措施。
- **可预测的输出大小。** 许多 agent 运行环境会在 tool 输出超过阈值（例如 10-30K 字符）后自动截断，可能丢失关键信息。如果 script 可能产生大量输出，请默认输出摘要或设置合理限制，并支持 `--offset` 之类的标志，让 agent 在需要时请求更多信息。或者，如果输出很大且不适合分页，应要求 agent 传入 `--output` 标志，用它指定输出 file，或传入 `-` 来明确选择输出到 stdout。
