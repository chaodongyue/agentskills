## directory 结构

一个 skill 是一个 directory，至少包含一个 `SKILL.md` file：

```
skill-name/
├──SKILL.md # 必需：metadata + instructions
├──scripts/ # 可选：executable code
├──references/ # 可选：documentation
├──assets/ # 可选：template、resource
└──... # 任何其他 file 或 directory
```

## `SKILL.md` 格式

`SKILL.md` file 必须先包含 YAML frontmatter，然后是 Markdown 内容。

### Frontmatter

| field | 必需| 约束 |
|-------|----------|-------------|
| `name` | 是 | 最多 64 个字符。只能包含小写字母、数字和连字符。不能以连字符开头或结尾。 |
| `description` | 是 | 最多 1024 个字符。不能为空。 描述该 skill 做什么以及何时使用。 |
| `license` | 否 | license 名称，或对打包 license file 的 reference。 |
| `compatibility` | 否 | 最多 500 个字符。 说明环境要求（目标产品、系统包、网络访问等）。 |
| `metadata` | 否 | 任意键值映射，用于附加 metadata。 |
| `allowed-tools` | 否 | 以空格分隔的字符串，列出该 skill 可使用的预批准 tool。（实验性） |

<Card>
**最小示例：**

```markdown SKILL.md
---
name: skill-name
description: 描述这个 skill 做什么以及何时使用。
---
```

**包含可选 field 的示例：**

```markdown SKILL.md
---
name: pdf-processing
description: 提取 PDF 文本、填写表单、合并文件。处理 PDF 时使用。
license: Apache-2.0
metadata:
 author: example-org
 version: "1.0"
---
```
</Card>

#### `name` field

必需的 `name` field：
- 必须为 1 到 64 个字符
- 只能包含 unicode 小写字母数字字符（`a-z`）和连字符（`-`）
- 不能以连字符（`-`）开头或结尾
- 不能包含连续连字符（`--`）
- 必须与父 directory 名称匹配

<Card>
**有效示例：**

```yaml
name: pdf-processing
```

```yaml
name: data-analysis
```

```yaml
name: code-review
```

**无效示例：**

```yaml
name: PDF-Processing # 不允许大写
```

```yaml
name: -pdf # 不能以连字符开头
```

```yaml
name: pdf--processing # 不允许连续连字符
```

</Card>

#### `description` field

必需的 `description` field：
- 必须为 1 到 1024 个字符
- 应同时 描述该 skill 做什么以及何时使用
- 应包含有助于 agent 识别相关 task 的具体关键词

<Card>
**好示例：**
```yaml
description: 从 PDF 文件 中提取文本和表格、填写 PDF 表单，并合并多个 PDF。处理 PDF 文档，或 user 提到 PDF、表单、 文档提取时使用。
```

**差示例：**
```yaml
description: 帮助处理 PDF。
```
</Card>

#### `license` field

可选的 `license` field：
- 指定应用于该 skill 的 license
- 建议保持简短（license 名称或打包 license file 的名称）

<Card>
**示例：**
```yaml
license: Proprietary. LICENSE.txt has complete terms
```
</Card>

#### `compatibility` field

可选的 `compatibility` field：
- 如果提供，必须为 1 到 500 个字符
- 只有当你的 skill 有特定环境要求时才应包含
- 可以 说明目标产品、所需系统包、网络访问需求等

<Card>
**示例：**
```yaml
compatibility: Designed for Claude Code (or similar products)
```
```yaml
compatibility: Requires git, docker, jq, and access to the internet
```
```yaml
compatibility: Requires Python 3.14+ and uv
```
</Card>

<Note>
大多数 skills 不需要 `compatibility` field。
</Note>

#### `metadata` field

可选的 `metadata` field：
- 从字符串键到字符串值的映射
- client 可以用它存储 Agent Skills specification 未定义的附加属性
- 建议让键名足够独特，以避免意外冲突

<Card>
**示例：**
```yaml
metadata:
 author: example-org
 version: "1.0"
```
</Card>

#### `allowed-tools` field

可选的 `allowed-tools` field：
- 一个以空格分隔的字符串，列出预批准运行的 tool
- 实验性 field。不同 agent 实现对此 field 的支持可能不同

<Card>
**示例：**
```yaml
allowed-tools: Bash(git:*) Bash(jq:*) Read
```
</Card>

### 正文内容

frontmatter 之后的 Markdown 正文包含 skill instructions。这里没有格式限制。只要能帮助 agent 有效完成 task，都可以写入。

推荐章节：
- 分步 instructions
- 输入和输出示例
- 常见边界情况

请注意，一旦 agent 决定激活 某个 skill，它会加载整个 file。对于较长的 `SKILL.md` 内容，可以考虑拆分到referenced 文件中。

## 可选 directory

### `scripts/`

包含 agent 可以运行的executable code。 script 应：
- 自包含，或清楚记录依赖项
- 包含有帮助的错误消息
- 优雅地处理边界情况

支持的语言取决于 agent 实现。常见选择包括 Python、 Bash 和 JavaScript。

### `references/`

包含 agent 可在需要时读取的附加 documentation：
- `REFERENCE.md` - 详细技术参考
- `FORMS.md` - 表单 template 或 structured 数据格式
- 领域特定 file（`finance.md`、`legal.md` 等）

保持单个[参考 file](#file-references)聚焦。 agent 会按需加载这些 file，因此 file 越小，占用的 context 越少。

### `assets/`

包含静态 resource：
- template（documentationtemplate、配置 template）
- 图片（图表、示例）
- 数据 file（查找表、 schema）

## progressive disclosure

agent 会*渐进式*加载 skills，只在 task 需要时引入更多细节。Skills 应按这种方式组织：

1. **metadata**（约 100 个 token）：启动时为所有 skills 加载 `name` 和 `description` field
2. **instructions**（建议少于 5000 个 token）：skill 激活时加载完整的 `SKILL.md` 正文
3. **resource**（按需）：只有在需要时才加载 file（例如 `scripts/`、`references/` 或 `assets/` 中的 file）

将主 `SKILL.md` 控制在 500 行以内。把详细参考资料移到单独 文件中。

## file reference

在 skill 中 reference 其他 file 时，请使用相对于 skill 根 directory 的路径：

```markdown SKILL.md
See [the reference guide](references/REFERENCE.md) for details.

Run the extraction script:
scripts/extract.py
```

让 file reference 距离 `SKILL.md` 保持一层深度。避免深层嵌套的 reference 链。

## validation

使用 [skills-ref](https://github.com/agentskills/agentskills/tree/main/skills-ref) 参考库 validation 你的 skills：

```bash
skills-ref validate ./my-skill
```

这会检查你的 `SKILL.md` frontmatter 是否有效，并是否遵循所有命名约定。
